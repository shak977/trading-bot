# Signal Desk — Design Handover

A working brief for redesigning the trading-signals dashboard. Read this before mocking anything up: the way the page is built imposes real constraints, and the design system already exists — the goal is to evolve it, not start from a blank canvas.

---

## 1. What it is & who it's for

**Signal Desk** is a US-equities trading-signals dashboard. An automated pipeline scans the market a few times a day, scores each candidate with a conviction checklist, and publishes a static site (GitHub Pages) with the current signals, charts, a paper-trading track record, and market context. It's a personal research tool for one experienced retail trader — dense, information-first, "Bloomberg-terminal-at-home" in spirit, not a consumer app.

Tone today: **dark-first, monospace-accented, data-dense.** Think terminal / trading desk, not fintech-consumer-friendly.

---

## 2. How the UI is built — READ THIS FIRST (hard constraint)

The entire site is **one self-contained `dashboard.html`**, generated by a giant Python f-string inside `dashboard.py` (the HTML/CSS/JS lives as a string literal, roughly lines 2850–5200). There is no framework, no build step, no component library.

Consequences for design work:
- **It must stay a single self-contained HTML file.** CSS is one big `<style>` block; JS is inline. The only external file is `chart_engine.js` (the candlestick/line chart renderer) and CDN libs.
- **Because it's an f-string, literal braces are doubled** — CSS `{{ }}`, JS template literals `${{...}}`, and single `{var}` is Python substitution. Any hand-authored CSS/JS a designer produces has to be brace-escaped when it goes back into `dashboard.py`. (Design in plain HTML/CSS first; escaping is a mechanical last step.)
- **No `localStorage` if you prototype as a Claude artifact** — artifacts block it. The live site itself does use it (for remembering layout/theme), so that's fine in production; just don't rely on it inside an artifact mockup.
- Mobile matters: the trader checks it on a phone. Everything is responsive today (max-width 1480px wrap, single-column collapse).

**Practical workflow for a designer:** mock screens as standalone HTML/CSS using the exact CSS variables below, get them looking right, then hand back — the escaping + wiring into `dashboard.py` is the implementation step.

## 3. Design tokens (current)

Default theme is **dark** (`<html data-theme="dark">`), with a light theme toggle. Tokens are CSS variables — always design against these, never hard-code hex.

**Fonts**
- Body: `Inter, -apple-system, Segoe UI, Roboto, sans-serif` — 15px / 1.5
- Mono (numbers, prices, tickers, badges): `ui-monospace, "SF Mono", "JetBrains Mono", Menlo, Consolas` (var `--mono`)

**Color tokens** (semantic — same names in both themes):

| token | dark | light | meaning |
|---|---|---|---|
| `--bg` | `#05080b` | `#f5f7fa` | page background |
| `--card` | `#0a1014` | `#ffffff` | card/surface |
| `--line` | `#1c2530` | `#e4e8ed` | borders/dividers |
| `--txt` | `#e6edf3` | `#16202c` | primary text |
| `--txt2` | `#c2cad4` | `#3d4757` | secondary text |
| `--muted` | `#8b97a6` | `#5b6776` | tertiary/labels |
| `--buy` | `#2ea043` | `#0a7d44` | long / positive |
| `--sell` | `#f85149` | `#d1242f` | short-loss / negative |
| `--hold` | `#58a6ff` | `#0b5cad` | hold |
| `--short` | `#fb7185` | `#c2410c` | short direction |
| `--watch` | `#94a3b8` | `#475569` | watch tier |

Radius ~7–10px on chips/cards. Conviction uses a red-amber-green (RAG) scale mapped to `--sell` / `--warn` / `--buy`.

## 4. Screen / navigation inventory

Left sidebar nav (primary pages) → `id="page-*"` sections:

- **Signals** (`page-signals`) — the home screen. Header (brand, PAPER badge, live clock, Refresh, theme toggle), a staleness banner, KPI summary strip, a layout switcher, and the signal cards. This is the screen that matters most.
- **Markets** (`page-markets`) — movers, most-active, market news, sector strength.
- **Portfolio** (`page-portfolio`) — paper positions, exposure, All-Weather panel.
- **Intel** (`page-altdata`) — the alt-data deep dive (catalyst, buzz, RS, TradingView, insider, analyst).
- **News** (`page-news`) — interleaved multi-source news + news-driven ideas.
- **System** (`page-system`) — what tools/integrations are running (feeds, AI, engine, scrapers, delivery, infra).
- **About / Method** (`page-method`) — how signals are generated.
- **Live TV** (`page-livetv`) — embedded Yahoo/Schwab finance video.

Secondary/detail pages that exist: `intraday`, `orb`, `pairs`, `paper`, `track`, `analyst`, `momentum`, `allweather`, `ipos`, `heatmap`.

## 5. The Signals screen in detail (primary redesign target)

**Layout switcher** — the signal list can render in 6 modes (buttons, default is **Terminal**):
`Cards`, `Lanes`, `Terminal`, `Gauges`, `Feed`, `Ticker`. Each is a different density/visual treatment of the same signals. (This is a lot of surface area — a design question is whether all six earn their keep.)

**Signal card** (Cards layout) shows: ticker + company, action pill (BUY / SHORT / WATCH / HOLD), conviction RAG badge + score, a sparkline, price, an age chip ("New today" / "N days old"), an "alerted today" chip, and target/entry/stop.

**Signal detail modal** (opens from any card/row) has sub-tabs (`data-mkview`):
`overview`, `plan` (trade plan + target scenarios), `signals` (Inputs — the alt-data breakdown), `chart`, `research`, `risk`, `rank`, `regimefit`, `strategies`, `newsread`, `exec`, `meta`. That's **12 sub-tabs** — dense, and a prime candidate for information-hierarchy work.

**KPI strip** — summary stats across the top (counts, track-record win rate, etc.).

## 6. Honest pain points & opportunities

These are the designer's brief — where it's weakest today:

- **Density vs. hierarchy.** It shows a lot, but the eye doesn't always know where to land first. The Signals screen could use a clearer primary→secondary→tertiary hierarchy (what's the ONE thing to look at?).
- **Six layouts + twelve modal sub-tabs** is a lot of optionality that may be diluting focus. Consider consolidating to the few that are genuinely useful.
- **Conviction is the core signal** but competes visually with everything else. It could be more of a hero element.
- **Mobile** works but is a compressed afterthought of the desktop density; a mobile-first pass on the Signals screen would help (it's where the phone checks happen).
- **The terminal aesthetic is good and worth keeping** — the opportunity is refinement (spacing, rhythm, typographic scale, restraint with color) rather than a restyle.
- Color: red/green is doing a lot of work; make sure it's accessible (the sell-red on dark is vivid) and that non-color cues exist.

---

## 7. Constraints any redesign must respect

1. Single self-contained HTML file; CSS variables for all color; no framework.
2. Keep both dark + light themes working off the token set.
3. Stay information-first and fast — no heavy imagery, no web fonts beyond what's already loaded, no layout that hides critical numbers behind interaction.
4. Charts are rendered by `chart_engine.js` (candles/line, zoom/pan) — design *around* that component, don't redesign the chart internals in this pass.
5. Responsive down to a phone.
6. Accessibility: don't rely on color alone for direction/conviction.

## 8. How to preview & iterate

- The live site: `shak977.github.io/trading-bot`.
- To see current state locally, the generated file is `dashboard.html` in the repo root (open in a browser).
- For mockups: build standalone HTML/CSS using the tokens in §3, at both desktop (~1480px) and mobile (~380px) widths, in dark and light.

## 9. Suggested focus for the design session

Pick one to go deep rather than restyling everything:

1. **Redesign the Signals home screen** — hierarchy, the hero conviction treatment, the KPI strip, and which layouts to keep. (Highest impact.)
2. **Redesign the signal detail modal** — collapse 12 sub-tabs into a clear, progressive-disclosure structure.
3. **Mobile-first Signals pass** — the phone experience specifically.

**Open questions to decide with the designer:**
- Keep all 6 layouts, or consolidate to 2–3?
- Should the default view be Terminal (current) or something calmer?
- How hero should conviction be — a big number/gauge, or kept inline?
- Any appetite to soften the terminal aesthetic toward something more readable, or keep it hardcore?
